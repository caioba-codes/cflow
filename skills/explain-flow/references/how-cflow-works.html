How cflow works

You give AI agents an idea. They plan it, build it, test it, review each other's work and merge it. You only step in at a few points.

1. What you need

  • Claude Code with a Claude Max plan. Several agents run at once and use up limits fast, so more than one Max plan works best.
  • Codex with a ChatGPT plan. A GPT model reviews the Claude agents' work and catches what they miss. Optional, but recommended.
  • GitHub, with the gh command installed. That's where agents open and merge their changes.
  • Your app, running on your computer, and a way for agents to use it: Claude in Chrome for web apps, tmux for command-line apps.

2. Set up

Once per computer

  1. git clone https://github.com/caioba-codes/cflow && cflow/scripts/install.sh
  2. Run /setup-cflow in Claude Code. Pick large when asked, confirm, then start a new chat.

Once per project

  1. Run /create-verification-skill. The agent learns to open your app and use it like a person, so every change gets tested for real. This step pays off the most.
  2. Add this line to the project's AGENTS.md or CLAUDE.md, so cflow is always on: Load the cflow skill first for any build, fix or plan task.

3. One feature, start to finish

Example: letting people comment on posts. Green rows are yours. Open an agent row only if you're curious.

Idea → plan

1youDescribe it in a line or two: "Let people comment on posts, and notify the post's author."
agent
It reads your code and tests its ideas
  • Subagents read the parts that matter: posts, sign-in, the database, notifications.
  • Quick throwaway experiments answer what a test can answer, like "can the app already send email?".
2youAnswer a few product questions. Each comes with a recommended answer: "Can people edit a comment?", "Email or in-app notifications?"
agent
It writes the plan
  • One part per pull request: storing comments, the comment box, notifications. Each says how it will be tested.
3youSay GO, plus autopilot-full (agents merge everything) or autopilot-stack (you do the final merge).

Plan → merged

agent
It builds, tests and reviews each part
  • One agent per part, in parallel. Each tests its change on your running app.
  • A different model, ideally GPT, reviews it and says PASS or FAIL. Only a PASS gets merged.
4youApprove screenshots of anything users will see, like the new comment box.
5youSay yes or no to deploys and anything that can't be undone, like emailing real users.

Merged → you understand it

6youRead the one-page explainer the agent writes and take its 5-question quiz. You keep understanding your code without reading every change.
Does the agent interview you first? No. Your first message is the brief, and it asks only what it can't figure out. Want an interview anyway? /cflow grill me first.
