How cflow works

You give AI agents an idea. They plan it, build it, test it, review each other's work and merge it. You only step in at a few points.

What you need

Claude Code with a Claude Max plan
Several agents run at once and use up limits fast, so more than one Max plan works best.
Codex with a ChatGPT planrecommended
A GPT model reviews the Claude agents' work and catches what they miss.
GitHub
Agents open and merge their changes there. Install the gh command too.
Your app, running on your computer
Agents need a way to use it: Claude in Chrome for web apps, tmux for command-line apps.

Once per computer

1

git clone https://github.com/caioba-codes/cflow && cflow/scripts/install.sh
2
In Claude Code, pick large when asked, confirm, then start a new chat
/setup-cflow

Once per project

3
Teach the agents to use your app
/create-verification-skill
The agent learns to open your app and use it like a person, so every change gets tested for real. This step pays off the most.
4
Add this line to the project's AGENTS.md or CLAUDE.md
Load the cflow skill first for any build, fix or plan task.
It keeps cflow on in every chat. Without it, /cflow only covers one message.

One feature, start to finish

Example: letting people comment on posts. The numbered steps are yours. Open the agent lines only if you're curious.

  1. Idea → plan
  2. 1
    Describe it in a line or two: "Let people comment on posts, and notify the post's author."
  3. It reads your code and tests its ideas
    • Subagents read the parts that matter: posts, sign-in, the database, notifications.
    • Quick throwaway experiments answer what a test can answer, like "can the app already send email?".
  4. 2
    Answer a few product questions. Each comes with a recommended answer: "Can people edit a comment?", "Email or in-app notifications?"
  5. It writes the plan
    • One part per pull request: storing comments, the comment box, notifications. Each says how it will be tested.
  6. 3
    Say GO, plus autopilot-full (agents merge everything) or autopilot-stack (you do the final merge).
  7. Plan → merged
  8. It builds, tests and reviews each part
    • One agent per part, in parallel. Each tests its change on your running app.
    • A different model, ideally GPT, reviews it and says PASS or FAIL. Only a PASS gets merged.
  9. 4
    Approve screenshots of anything users will see, like the new comment box.
  10. 5
    Say yes or no to deploys and anything that can't be undone, like emailing real users.
  11. Merged → you understand it
  12. 6
    Read the one-page explainer the agent writes and take its 5-question quiz. You keep understanding your code without reading every change.

Does the agent interview you first? No. Your first message is the brief, and it asks only what it can't figure out. Want an interview anyway? /cflow grill me first
